# Start here

**Sentinel is a confidential systemic-risk oracle for DeFi lending: it measures how much borrowed value sits with addresses levered across more than one protocol on the same collateral, and it computes that inside a Chainlink CRE TEE because the per-address map it needs is itself the harm.**

## The one command that proves everything

```sh
cp .env.example .env.local   # set GRAPH_API_KEY, and SENTINEL_RISK_POLICY as documented in the file
npm ci
npm run verify
```

18 stages against live mainnet data, no mocks, 120.5 seconds on the last full run. It prints a pass or fail line per stage and a total, and it re-derives the headline figures from scratch: 37,862 accounts scanned across 5 Messari standardized lending deployments, $35,923,754 levered across more than one protocol on the same collateral, composite score 2201 bps. Stages that need an absent toolchain skip with a printed reason rather than failing silently. `npm run preflight` alone tells you whether your setup can produce real numbers before anything else runs.

## Read these four files, in this order

1. **[`docs/EVIDENCE.md`](docs/EVIDENCE.md)** every qualification bullet from all three tracks, in the sponsors' own wording, mapped to the file, line and artifact that answers it. If you read only one file, read this one.
2. **[`docs/ENCLAVE.md`](docs/ENCLAVE.md)** the confidentiality claim made checkable: every value crossing into or out of the TEE, why it is on the side it is on, and why the enumeration is complete rather than a summary.
3. **[`docs/SIGNAL.md`](docs/SIGNAL.md)** the integration contract. `SentinelConsumer.sol` was written from this document alone, so it is the test of whether the spec is sufficient.
4. **[`docs/AGENT.md`](docs/AGENT.md)** the 8 tools, the citation invariant, and the refusals. The interesting claim is that the tools constrain the model rather than assist it.

The README's "What I Do Not Claim" section is the fastest way to calibrate everything else.

## Where the evidence lives

Everything is under [`docs/evidence/`](docs/evidence/), committed rather than regenerated at read time:

- `cre-simulation.log` the CRE CLI simulation, exit 0, with the CLI's own line confirming TEE dispatch to AWS Nitro in `us-west-2`.
- `phase7-mcp-handshake.log` real JSON-RPC frames from an MCP client: `initialize`, `tools/list`, `tools/call`.
- `phase7-transcript.md` 10 questions against live subgraphs, 8 answered and 2 refused, every numeral audited against its citation table by a test that re-parses this file.
- `phase8-forge.log` 37 forge tests passing, 24 on the consumer and 13 on the guarded vault.
- `leak-demo.md` and `consume-signal.md` what the enclave withholds, and one accept against 7 refused tampered variants.
- `screens/` 10 screenshots, both themes, regenerated by `npm run capture:ui`.
- `casts/` the terminal casts, committed with per-chunk timings. The demo video is rendered from these frame by frame rather than screen-recorded, so any frame of it can be diffed against the bytes the command actually printed.

The 3:57 demo video is at [`docs/demo.mp4`](docs/demo.mp4) and plays inline at the top of the README.

## The one thing you need to run it

A **Graph API key** from [thegraph.com/studio](https://thegraph.com/studio), in `.env.local` as `GRAPH_API_KEY`. That is the only credential the core path needs. There is no mock mode, and `lib/__tests__/no-mock-data.test.ts` fails the build if one ever appears.
